# 为什么除以 dk\sqrt{d_k}dk​​？

在各维独立、均值为 0、方差为 1 的简化假设下，点积 qi⊤kjq_i^\top k_jqi⊤​kj​ 的方差约为 dkd_kdk​，标准差约为 dk\sqrt{d_k}dk​​。除以 dk\sqrt{d_k}dk​​ 能控制得分的尺度，避免维度增大时 softmax 的输入变大导致饱和、梯度变小甚至消失。

# NumPy 实现

不同的头使用不同的可学习投影，可以从不同的表示子空间计算注意力。例如，有的头可能更关注局部位置，有的头可能更关注远距离关系；这些分工是训练中学到的，并非预先规定。

每个头计算的是长度为 (d_k) 的 Query 与 Key 的点积，所以应按单头的 Key 维度缩放。

# 自回归生成

这里讨论最基本的 Decoder-only、因果 Multi-Head Self-Attention。设 Batch 大小为 BBB，当前序列长度为 LLL，注意力头数为 hhh，每个头的 Query/Key 维度为 dkd_kdk​，Value 维度为 dvd_vdv​。以下过程在每一层 Attention 中分别进行，每层都有自己的 KV Cache。

# Prefill：处理已有的 LLL 个 token

Q,K∈RB×h×L×dk,V∈RB×h×L×dv.Q,K\in\mathbb{R}^{B\times h\times L\times d_k}, \qquad V\in\mathbb{R}^{B\times h\times L\times d_v}.Q,K∈RB×h×L×dk​,V∈RB×h×L×dv​.

使用因果掩码计算注意力：位置 iii 只能关注位置 111 到 iii。

# KV Cache

没有 KV Cache，每生成一个 token，都需要为整个已有序列重复计算过去 token 的 K、V。有了 Cache，每一步只计算新 token 的 Q、K、V，并读取过去保存的 K、V。

KV Cache 没有消除当前 Query 与历史 Key 的注意力计算：当前步仍须关注约 LLL 个已有位置。因此，基本密集 Attention 的单步注意力计算量仍随当前序列长度增长；KV Cache 换取计算效率的代价是持续占用显存。

# Sliding Window Attention

Sliding Window Attention 保留基本 Attention 的打分方式，主要改变的是每个 Token 可以关注哪些位置。在因果注意力中，位置 iii 原本可以关注所有满足 j≤ij\le ij≤i 的位置；加入大小为 www 的滑动窗口后，只能关注最近的 www 个位置：

i−w+1≤j≤i.i-w+1\le j\le i.i−w+1≤j≤i.

主要作用是降低长序列开销：每个 Token 最多与 www 个位置计算注意力，计算量从 O(n2)O(n^2)O(n2) 降为 O(nw)O(nw)O(nw)（如果仅仅使用加性因果掩码则不会降低计算量）。逐 Token 生成时，超出窗口的历史 Key 和 Value 也可以从该层的缓存中移除。代价是单层无法直接读取窗口之外的信息。较早的信息仍可通过中间 Token 在多层之间逐步传递，但需要精确访问远处内容时，有限窗口可能造成信息损失。

# Sparse Attention

Sparse Attention 的核心是：每个 Query 只与选定的一部分 Key 计算注意力，不再计算完整的 n×nn\times nn×n 分数矩阵。它是一类方法；Sliding Window Attention 就是采用固定局部连接的一种稀疏注意力。

为了让远距离信息也能交互，其他稀疏模式还会加入全局连接（让少量重要 Token 关注整个序列）、随机连接，或根据内容选择相关位置。不同方法的主要区别，正是如何选出这些连接，也可以根据 Q，K 动态选择连接。

若每个 Query 平均只连接 sss 个 Key，整个序列约计算 nsnsns 个注意力分数，复杂度从 O(n2)O(n^2)O(n2) 降为 O(ns)O(ns)O(ns)。但稀疏连接也可能漏掉重要的 Token 对；在因果生成中，选中的位置还必须满足 j≤ij\le ij≤i，不能读取未来信息。

# Routing Attention

Routing Attention 是一种按内容动态选择连接的稀疏注意力。让内容相关的 Query 和 Key 有机会相互关注，即使它们在序列中相距很远。

以 Routing Transformer 为例，它使用在线 kkk-means 学习聚类中心，根据向量与聚类中心的相似度，在每一层将 Query 和 Key 分配到相应的簇。第 iii 个 Query 主要与路由到同一簇的 Key 计算注意力；在因果生成中，还须排除未来位置，即只保留 j≤ij\le ij≤i 的 Key。

核心收益是跳过大量内容不相关的 Query–Key 点积。论文所采用的设置将注意力复杂度从 O(n2d)O(n^2d)O(n2d) 降至约 O(n1.5d)O(n^{1.5}d)O(n1.5d)，其中 nnn 是序列长度、ddd 是特征维度。它的代价是需要额外的路由和聚类计算；如果相关的 Query 与 Key 被分到不同簇，它们就可能无法直接交互。

# Linformer Attention

Linformer 的核心改动是：先沿序列长度维度压缩 Key 和 Value，再计算注意力。它基于一个近似假设：虽然标准 Attention 会产生 n×nn\times nn×n 的注意力矩阵，但其中的信息可以用较低秩的结构表示。

设序列长度为 nnn，Linformer 使用两个可学习的投影矩阵 E,F∈Rk×nE,F\in\mathbb{R}^{k\times n}E,F∈Rk×n，其中 k≪nk\ll nk≪n。它们分别把 Key 和 Value 从 nnn 个位置压缩到 kkk 个位置：

K~=EK,V~=FV.\widetilde K=EK,\qquad \widetilde V=FV.K=EK,V=FV.

随后，所有 nnn 个 Query 与压缩后的 kkk 个 Key 计算注意力：

Linformer⁡(Q,K,V)=softmax⁡(QK~⊤dk)V~.\operatorname{Linformer}(Q,K,V) = \operatorname{softmax}\left( \frac{Q\widetilde K^\top}{\sqrt{d_k}} \right)\widetilde V.Linformer(Q,K,V)=softmax(dk​​QK⊤​)V.

标准 Attention 的分数矩阵大小为 n×nn\times nn×n；Linformer 将其变为 n×kn\times kn×k。当 kkk 远小于 nnn 且不随 nnn 增长时，注意力计算与存储开销随序列长度约为 O(nk)O(nk)O(nk)，而不是 O(n2)O(n^2)O(n2)。

代价是压缩可能丢失特定位置的细节。此外，原始投影就会混合整个序列的位置：若直接用于自回归生成，前面位置的压缩表示可能包含未来信息，因此不能直接把 Linformer 形式当作因果 Attention 使用。

# Linear Attention

标准 Attention 需要让每个 Query 与所有 Key 计算分数，形成大小为 n×nn\times nn×n 的注意力矩阵。Linear Attention 的核心思路是：改写 Query–Key 的相似度，使 Key 和 Value 能先汇总，再与 Query 交互。

设 ϕ(⋅)\phi(\cdot)ϕ(⋅) 是将向量映射到 rrr 维的特征映射。用 ϕ(qi)⊤ϕ(kj)\phi(q_i)^\top\phi(k_j)ϕ(qi​)⊤ϕ(kj​) 表示 Query 与 Key 的相似度后，第 iii 个位置的输出可以写为：

因果 Attention 只能使用当前位置及之前的 Token。此时维护两个随序列更新的汇总量即可：

Si=Si−1+ϕ(ki)vi⊤,zi=zi−1+ϕ(ki),S_i=S_{i-1}+\phi(k_i)v_i^\top,\qquad z_i=z_{i-1}+\phi(k_i),Si​=Si−1​+ϕ(ki​)vi⊤​,zi​=zi−1​+ϕ(ki​),

oi=ϕ(qi)⊤Siϕ(qi)⊤zi.o_i=\frac{\phi(q_i)^\top S_i}{\phi(q_i)^\top z_i}.oi​=ϕ(qi​)⊤zi​ϕ(qi​)⊤Si​​.

新 Token 到来时，更新 SiS_iSi​ 和 ziz_izi​，不必重新遍历全部历史 Key 和 Value。在固定特征维度 rrr 与 Value 维度 dvd_vdv​ 下，整个序列的核心计算量约为 O(nrdv)O(nrd_v)O(nrdv​)，对序列长度 nnn 呈线性增长。

# Performer Attention

Performer 是一种旨在以线性复杂度近似标准 Softmax Attention 的方法。它属于 Linear Attention，但与直接选用 ϕ(x)=ELU⁡(x)+1\phi(x)=\operatorname{ELU}(x)+1ϕ(x)=ELU(x)+1 不同：Performer 专门构造特征映射，使映射后的点积尽量接近 Softmax 使用的指数相似度。

标准 Attention 在归一化前使用 exp⁡(q⊤k/d)\exp(q^\top k/\sqrt d)exp(q⊤k/d​) 作为 Query–Key 的相似度。Performer 的 FAVOR+ 使用正值随机特征，将其近似为两个特征向量的点积：

exp⁡(q⊤k/d)≈ϕ(q)⊤ϕ(k).\exp(q^\top k/\sqrt d)\approx\phi(q)^\top\phi(k).exp(q⊤k/d​)≈ϕ(q)⊤ϕ(k).

为简化表达，令 x=q/d1/4x=q/d^{1/4}x=q/d1/4 或 x=k/d1/4x=k/d^{1/4}x=k/d1/4。特征映射的一种基本形式为：

ϕ(x)=e−∥x∥2/2r[eω1⊤x,eω2⊤x,…,eωr⊤x],\phi(x)= \frac{e^{-\lVert x\rVert^2/2}}{\sqrt r} \left[ e^{\omega_1^\top x}, e^{\omega_2^\top x}, \ldots, e^{\omega_r^\top x} \right],ϕ(x)=r​e−∥x∥2/2​[eω1⊤​x,eω2⊤​x,…,eωr⊤​x],

其中 rrr 是随机特征数，ω1,…,ωr\omega_1,\ldots,\omega_rω1​,…,ωr​ 是随机投影向量。FAVOR+ 进一步采用正交随机特征来降低近似误差。

有了 ϕ(q)⊤ϕ(k)\phi(q)^\top\phi(k)ϕ(q)⊤ϕ(k)，就可以先汇总所有 Key 和 Value，再处理每个 Query：

oi≈ϕ(qi)⊤(∑jϕ(kj)vj⊤)ϕ(qi)⊤(∑jϕ(kj)).o_i\approx \frac{ \phi(q_i)^\top\left(\sum_j\phi(k_j)v_j^\top\right) }{ \phi(q_i)^\top\left(\sum_j\phi(k_j)\right) }.oi​≈ϕ(qi​)⊤(∑j​ϕ(kj​))ϕ(qi​)⊤(∑j​ϕ(kj​)vj⊤​)​.

这样无需显式生成 n×nn\times nn×n 的注意力矩阵。固定特征数 rrr 和 Value 维度时，计算量随序列长度 nnn 线性增长；因果生成时，括号内的汇总量也可以随新 Token 到来递增更新。Performer 计算的是 Softmax Attention 的近似结果。增大 rrr 通常有助于提高近似精度，但也会增加计算和存储开销。

# Multi-Query Attention（MQA）

Multi-Query Attention 主要针对自回归生成时的 KV Cache 开销。标准多头注意力（MHA）为每个 Query 头配备独立的 Key 头和 Value 头；MQA 保留多个 Query 头，但让所有 Query 头共享同一组 Key 和 Value。

设输入为 X∈RB×n×dmodelX\in\mathbb{R}^{B\times n\times d_{\text{model}}}X∈RB×n×dmodel​，Query 头数为 HHH，每个头的维度为 dhd_hdh​。假设 Key 和 Value 的头维度也都是 dhd_hdh​：

张量标准 MHAMQA
Query QQQB×H×n×dhB\times H\times n\times d_hB×H×n×dh​B×H×n×dhB\times H\times n\times d_hB×H×n×dh​
Key KKKB×H×n×dhB\times H\times n\times d_hB×H×n×dh​B×1×n×dhB\times 1\times n\times d_hB×1×n×dh​
Value VVVB×H×n×dhB\times H\times n\times d_hB×H×n×dh​B×1×n×dhB\times 1\times n\times d_hB×1×n×dh​

变化只发生在 KV 的头数维度：从 HHH 变为 111。 生成 K,VK,VK,V 的投影输出维度，也分别从 HdhHd_hHdh​ 降为 dhd_hdh​；Query 的投影输出维度仍是 HdhHd_hHdh​。

计算第 hhh 个头时，仍使用该头自己的 Query，但读取所有头共享的 K,VK,VK,V：

Oh=softmax⁡(QhK⊤dh)V.O_h=\operatorname{softmax}\left(\frac{Q_hK^\top}{\sqrt{d_h}}\right)V.Oh​=softmax(dh​​Qh​K⊤​)V.

因此，各头虽然共享 KV，注意力权重仍可能不同，因为它们的 Query 不同。

每生成一个 Token，MHA 在每层需要向 KV Cache 写入约 2Hdh2Hd_h2Hdh​ 个元素；读取历史 KV 的数据量也随之降低。MQA 主要节省的是 KV Cache 容量和生成时的访存开销。各 Query 头仍需分别与历史位置计算注意力，因此它本身不会把注意力对序列长度的计算复杂度从平方变为线性。

# Grouped-Query Attention（GQA）

Grouped-Query Attention 将多个 Query 头分成若干组，每组共享一组 Key 和 Value。它在标准多头注意力（MHA）与 Multi-Query Attention（MQA）之间，提供了一个可调节的 KV 头数。

设有 HHH 个 Query 头、GGG 个 KV 组，且 HHH 能被 GGG 整除；每组包含 H/GH/GH/G 个 Query 头。各张量的形状为：

张量形状
Query QQQB×H×n×dhB\times H\times n\times d_hB×H×n×dh​
Key KKKB×G×n×dhB\times G\times n\times d_hB×G×n×dh​
Value VVVB×G×n×dhB\times G\times n\times d_hB×G×n×dh​

第 hhh 个 Query 头使用自己所属组的 Kg,VgK_g,V_gKg​,Vg​：

Oh=softmax⁡(QhKg⊤dh)Vg,g=⌊hH/G⌋.O_h=\operatorname{softmax}\left(\frac{Q_hK_g^\top}{\sqrt{d_h}}\right)V_g, \qquad g=\left\lfloor\frac{h}{H/G}\right\rfloor.Oh​=softmax(dh​​Qh​Kg⊤​​)Vg​,g=⌊H/Gh​⌋.

例如，H=32H=32H=32、G=8G=8G=8 时，每 4 个 Query 头共享一组 KV；不同 Query 头仍会计算各自的注意力权重。

  • G=HG=HG=H：每个 Query 头有独立 KV，即 MHA。
  • 1<G<H1<G<H1<G<H：多个 Query 头共享一组 KV，即 GQA。
  • G=1G=1G=1：全部 Query 头共享同一组 KV，即 MQA。

生成一个 Token 时，每层 KV Cache 需要存储约 2Gdh2Gd_h2Gdh​ 个元素，而 MHA 需要 2Hdh2Hd_h2Hdh​ 个。因此，GGG 越小，KV Cache 和访存开销越低；GGG 越大，各组拥有越独立的 KV 表示。GQA 通过选择 GGG 在两者之间取舍，但与 MQA 一样，并不改变各 Query 头仍须关注历史位置这一计算方式。

# PagedAttention

PagedAttention 将每个请求的 KV Cache 划分为固定大小的块（Block），允许这些块分散存放在显存中，再通过块表（Block Table）记录其对应关系。PagedAttention 借鉴操作系统的分页思想：逻辑上连续的 Token，其 KV Cache 可以存放在物理上不连续的显存块中，并随着序列增长按需分配。

PagedAttention 减少显存碎片和过度预留，并支持 KV 块共享，使相同显存能够容纳更多并发请求，提高服务吞吐量。
